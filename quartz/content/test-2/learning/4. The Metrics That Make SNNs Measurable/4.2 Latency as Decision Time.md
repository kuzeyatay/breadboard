### Latency as Decision Time

Once spikes carry information through time, an SNN prediction becomes a small race from the moment a stimulus appears to the moment the network has enough spike evidence to choose an output. Imagine an event-based gesture sensor watching a hand begin to move. The input does not arrive as one frozen image; it arrives as a stream of events. A useful model must decide quickly enough for the decision to still be useful. If the model waits too long, the gesture may already have changed. If it decides early with too little evidence, the answer may be unreliable. Latency gives this timing behavior a number.

Latency measures how quickly a decision emerges after a stimulus begins. The stimulus is the input event the system is asked to interpret: a spoken sound, a gesture, a visual change, or one sample from a benchmark dataset. The **stimulus onset time** is the clock time when that input begins. The **decision time** is the clock time when the model produces its chosen output. The **latency** is the elapsed time between those two moments:

$$
\text{Latency} = t_{\text{decision}} - t_{\text{stimulus onset}}
$$
Here, $t_{\text{stimulus onset}}$ means the time when the input starts, $t_{\text{decision}}$ means the time when the model commits to an output, and latency is the difference between them, usually measured in milliseconds. This formula lets you compute the decision delay directly. If a gesture begins at $0$ ms and the model classifies it at $10$ ms, the latency is $10 - 0 = 10$ ms. If a sound begins at $5$ ms and the model decides at $20$ ms, the latency is $20 - 5 = 15$ ms. The absolute clock times can shift, but the gap between them is the measurement that matters.

A beginner often asks where the decision happens in a spiking system, because spikes keep arriving over time. The answer is that a decision is tied to a chosen readout rule. A model may decide when one output neuron reaches a threshold, when one class accumulates the strongest spike evidence, or when a fixed simulation window ends and the accumulated activity is read. The metric stays the same: mark the stimulus onset, mark the decision time, then measure the gap. Latency turns a time-dependent process into a comparable number.

The phrase **simulation window** names the span of simulated time the model is allowed to use before the output is read. A short window forces the model to decide from early spikes. A longer window gives the network more time to accumulate spike evidence. Converted SNNs often need longer simulation windows because they approximate continuous ANN activations using spike rates over time. A rate estimate becomes clearer when more spikes have been observed, so the decision can require extra simulated time. That extra time shows up as higher latency. Directly trained spiking models can learn spike patterns that support earlier decisions, so they can reach useful outputs with shorter windows.

**Question.** If two models reach similar accuracy, why would latency still affect which one is chosen?

**Answer.** Accuracy tells how often the model is right, while latency tells how quickly the model becomes ready to answer. In a time-dependent spiking system, a correct answer that arrives late may be less useful for a live sensor stream. If a surrogate gradient SNN decides in about 10 ms and a converted SNN needs about 20 ms, the faster model can react earlier even when both models classify well.

A common confusion is to treat latency as the same thing as training speed. Training speed describes how quickly a model learns during optimization, often measured across epochs. Latency describes how quickly a trained model makes one inference after a stimulus begins. A model can converge quickly during training and still have a long inference delay if its decision rule waits for a long simulation window. A model can also train slowly and later make reasonably fast decisions once its spike timing has stabilized. Latency belongs to the moment of use: stimulus in, decision out.

**Question.** Why can a longer simulation window increase latency in a converted SNN?

**Answer.** A converted SNN often represents ANN-like activation strength through spike rates. Estimating a rate requires observing spikes over time. When the model needs a longer window to gather enough spike evidence, the decision time moves later, so $t_{\text{decision}} - t_{\text{stimulus onset}}$ becomes larger. The model may remain accurate, but its decision emerges more slowly.

Latency makes spiking behavior measurable because it links the internal timing of spikes to an external task requirement. A stimulus starts the clock. Spikes flow through the network and accumulate evidence. A decision rule marks the moment the model has enough evidence to answer. The distance between those two times is latency. Once that distance is measured in milliseconds, different models can be compared on the same practical question: how long does this system need before it can act?
