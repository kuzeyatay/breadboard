## Latency as Decision Time

Once accuracy tells us whether an SNN usually chooses the right class, the next measurement asks how long the network takes to make that choice. Imagine a small vision sensor on a drone watching for a hand gesture. The scene changes, the sensor begins producing input spikes, and the network starts accumulating evidence. A correct answer that arrives quickly can help the drone react while the gesture is still useful. A correct answer that arrives too late may describe the world after the moment for action has already passed. Latency gives that waiting time a number.

A spiking neural network works over time because its signals are events. A neuron may stay silent for a while, then emit a spike when its internal state reaches a firing threshold. Downstream neurons receive those spikes, update their own internal states, and may fire in response. Since evidence arrives as a sequence, the model's answer can emerge earlier or later depending on how quickly enough spikes support one decision. Latency measures that emergence. It turns the behavior "the network responded quickly" into a measurable signal: the time gap between the beginning of the input and the moment the network makes its decision.

The beginning of the input is called the **stimulus onset time**. A stimulus is the event or pattern presented to the network, such as a visual gesture, an audio clip, or an image encoded into spikes. The onset time is the clock time when that stimulus begins. The network's **decision time** is the clock time when the model has produced the output used as its answer. In a classification task, this might be the first moment when one output neuron crosses a decision threshold, or the end of a short observation window when the largest accumulated output is selected. The exact decision rule must be fixed before comparison, because latency only becomes meaningful when "decision" means the same thing across models.

The metric is simple once those two moments are defined:
$$
\text{latency} = t_{\text{decision}} - t_{\text{onset}}
$$
Here, $\text{latency}$ is the response time of the network, usually measured in milliseconds for real-time tasks. $t_{\text{decision}}$ is the time at which the model's answer is available. $t_{\text{onset}}$ is the time at which the stimulus begins. The subtraction computes how much time passes between the start of the input and the answer. If a gesture begins at $0$ milliseconds and the SNN makes its classification at $8$ milliseconds, then the latency is $8 - 0 = 8$ milliseconds. If another model waits until $35$ milliseconds, its latency is $35$ milliseconds under the same onset and decision rule.

This formula is powerful because it separates speed from correctness. Accuracy asks, "Was the answer right?" Latency asks, "When did the answer become available?" A model can be accurate but slow, or slightly less accurate but fast enough for an edge device that must respond in real time. For example, gesture-recognition systems using event-based vision sensors can benefit from SNNs because the input itself arrives as changes over time. A surrogate-trained SNN reaching decisions in roughly $5$-$10$ milliseconds can support real-time interaction, while an ANN counterpart taking $20$-$50$ milliseconds may feel delayed in a tight control loop. The latency number translates an internal computation into a practical question: can the system act while the moment still matters?

Latency also helps separate performance from cost. Energy consumption measures how much power the network spends. Spike count measures how many spike events the network uses. Latency measures how long the network waits before deciding. These metrics influence one another, but they answer different questions. A network that emits many spikes very quickly may have low latency but higher energy use. A network that emits very few spikes may save energy but need a longer observation window before the output is reliable. Measuring latency alongside energy and spike count prevents speed from being hidden inside a single accuracy score.

A beginner confusion often appears here: if spikes are efficient, it is tempting to assume fewer spikes always means faster decisions. Fewer spikes can reduce computation, especially on neuromorphic hardware, but the timing of useful spikes matters just as much as the number of spikes. If the decisive spikes arrive early, the network can answer early. If the network needs to wait for later evidence, the decision time moves later even when the total spike count stays small. Latency depends on when enough evidence has accumulated, not only on how many events occur.

**Question.** If two SNNs both classify the same gesture correctly, why might latency still change which one is better for deployment?

**Answer.** The lower-latency SNN produces its answer sooner after the gesture begins. In a real-time system such as robotics, gesture control, or edge sensing, the usefulness of a correct classification depends on whether the system can act quickly enough. If one network answers in $8$ milliseconds and another answers in $40$ milliseconds, both may be accurate, but the $8$-millisecond network gives the controller more time to respond.

The idea becomes clearer if we think of the network as a listener waiting for enough clues. At stimulus onset, the listener hears the first sound. Each spike is another clue. The listener makes a decision when the evidence is strong enough under the chosen rule. Latency is the elapsed time between the first sound and that decision. A low-latency SNN is a listener that needs only a short burst of well-timed evidence. A high-latency SNN is a listener that waits longer before becoming confident.

In converted SNNs, longer simulation windows can increase latency because the network may need more time steps to approximate the behavior of a continuous-valued ANN. In directly trained SNNs, especially those trained with surrogate gradient methods, the network can learn to use spike timing more directly, often producing faster and sparser computation. That is why latency belongs beside accuracy in any serious evaluation of SNNs. Accuracy alone can reward a model that eventually gets the right answer, while latency reveals whether the answer arrives soon enough for the task.

**Question.** What must be defined before latency can be compared fairly across two SNN models?

**Answer.** Both models need the same stimulus onset definition and the same decision rule. The onset definition fixes when the clock starts. The decision rule fixes when the clock stops, such as the first output threshold crossing or the end of a fixed observation window. Without matching these definitions, two latency values may describe different measurement procedures rather than genuine differences in response speed.

Latency completes a mental model of SNN behavior as time-shaped computation. The stimulus starts the clock, spikes carry evidence forward, output activity accumulates into a decision, and the decision stops the clock. The resulting number measures how quickly the network converts an input event into an actionable answer. When latency is measured together with accuracy, energy, and spike count, an SNN can be evaluated as a working real-time system rather than only as a classifier that eventually produces a label.
