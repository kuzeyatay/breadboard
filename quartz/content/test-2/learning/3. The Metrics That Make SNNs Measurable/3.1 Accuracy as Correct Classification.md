## Accuracy as Correct Classification

After a spiking network has turned an input into a prediction, the simplest question is whether that prediction matches the correct class. Imagine a small vision system watching handwritten digits. One image contains a 7, the network produces the label "7," and that decision counts as correct. Another image contains a 3, the network produces "8," and that decision counts as incorrect. Once the network has made many such decisions, a single example no longer tells us much. We need a way to describe the whole batch of behavior at once, so we count how often the network is right.

Accuracy is the metric that turns those repeated right-or-wrong decisions into one measurable number. A classification task always has a set of possible labels, such as digits from 0 to 9 or gesture categories from a sensor. Each input leads to one predicted label. If the predicted label matches the true label, it is a correct prediction. If the predicted label differs from the true label, it is an incorrect prediction. Accuracy asks: out of all the predictions the model made, what fraction were correct?

That counting idea leads directly to the formula:
$$
\text{Accuracy} = \frac{\text{number of correct predictions}}{\text{total number of predictions}}
$$
Here, **accuracy** is the fraction of decisions that are correct. The **number of correct predictions** is the count of inputs for which the model's predicted class equals the true class. The **total number of predictions** is the full count of inputs the model attempted to classify. The formula lets you compute classification performance from ordinary counts, before thinking about how the network produced those decisions internally.

For example, suppose an SNN classifies 100 test images and gives the correct label for 96 of them. Its accuracy is
$$
\frac{96}{100} = 0.96
$$
Written as a percentage, this is 96%. The percentage form says the same thing in a more familiar scale: 96 out of every 100 decisions were correct. If another model classifies 1,000 images and gets 960 correct, it also has 96% accuracy, because the fraction is the same:
$$
\frac{960}{1000} = 0.96
$$
The larger test set gives more evidence about the model's behavior, but the accuracy value still means the same kind of thing: the share of decisions that matched the correct labels.

S1.P6.E1 belongs exactly here because it captures accuracy as a count-based fraction: correct predictions divided by total predictions. The numerator is about successful classification decisions, and the denominator is about all classification attempts. The formula does not inspect spike timing, energy use, simulation length, or the number of spike events. It answers one narrow and useful question: how often did the model choose the right class?

This narrowness is what makes accuracy easy to understand and easy to misuse. In an ordinary artificial neural network, a prediction often comes from dense numerical computations. In a spiking neural network, a prediction comes from spike events unfolding over time. Two SNNs can reach the same final label accuracy while behaving very differently on the way there. One may produce many spikes over a longer simulation window. Another may reach a decision with fewer spikes and less delay. Accuracy treats both models as equal if they end with the same number of correct class labels.

A concrete example makes the limitation visible. Suppose two spiking classifiers each process 100 sensor inputs. Model A gets 97 correct, so its accuracy is 97%. Model B also gets 97 correct, so its accuracy is also 97%. If Model A needs about 10 milliseconds to reach each decision while Model B needs a much longer window, the equal accuracy hides a timing difference that would matter in a robot avoiding an obstacle. If Model A uses moderate energy per inference while Model B uses far more spike activity to arrive at the same labels, the equal accuracy hides a cost difference that would matter on a battery-powered edge device.

Accuracy therefore measures correctness, not cost. It tells us whether the classification result is right, but it does not tell us how expensive that result was to produce. In SNNs, cost is closely tied to the event-based nature of computation. A spike is a discrete event, and a network that can solve a task with fewer useful events may be more attractive for low-power hardware. A network that waits longer before deciding may still be accurate, but the delay can make it unsuitable for real-time sensing. Accuracy sees the finished answer; latency and energy describe part of the path taken to reach that answer.

**Question.** If two SNNs both reach 95% accuracy, should we treat them as equally good?

**Answer.** They are equally good only with respect to the fraction of correct classifications. They may differ strongly in how long they take to decide, how much energy they consume, and how much spiking activity they generate. For a task with no strict timing or power constraints, equal accuracy may be enough for an initial comparison. For a deployed SNN on edge or neuromorphic hardware, the same accuracy can hide practical differences that determine which model is usable.

Accuracy also depends on the collection of examples being counted. If a model is tested on easy examples, its accuracy may look high. If the examples are more varied or the classification problem becomes larger, accuracy can drop because the decision boundaries become harder to learn. In SNN evaluation, this means accuracy gives a measurable starting point, but it gains meaning from the testing situation around it. A 97% value on one task and a 97% value on another task may reflect different levels of difficulty.

The beginner confusion often comes from treating accuracy as a complete score for intelligence or efficiency. Accuracy is better understood as a correctness meter. It measures how often the network's final class decision matches the target label. It does not measure whether the spikes were sparse, whether the decision arrived quickly, whether the training stabilized smoothly, or whether the energy budget was small. Those are separate properties of the computation, and SNNs are interesting precisely because their event-based behavior can change those properties.

**Question.** Why use accuracy at all if it misses energy and latency?

**Answer.** Accuracy is still the cleanest way to check whether the model is solving the classification task. Before asking whether an SNN is fast or energy-efficient, we need to know whether its predictions are correct often enough to be useful. Accuracy provides that foundation. Once correctness is measurable, other metrics can be added to judge whether the same correctness is achieved with acceptable timing and cost.

A useful mental model is to picture accuracy as the scorekeeper at the finish line of classification. Each input crosses the line with a predicted label, and accuracy marks the result as right or wrong. That scorekeeper is necessary because it turns many individual decisions into one readable measure of classification performance. Yet the scorekeeper does not watch the whole race. For an SNN, the path to the finish line includes spike events, decision time, and energy use. Accuracy tells us how many answers were right; a full evaluation asks how the network managed to be right.
