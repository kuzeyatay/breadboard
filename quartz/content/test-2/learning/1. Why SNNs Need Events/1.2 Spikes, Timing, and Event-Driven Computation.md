## Spikes, Timing, and Event-Driven Computation

Imagine a sensor watching a hallway after the previous lesson's time-series idea is already in place. Most moments look almost the same: the wall stays still, the floor stays still, and the lighting changes only slightly. A network built around continuous activations would keep carrying a value for every unit at every step, even during the quiet stretches. Each layer receives arrays of numbers, transforms them, and passes new arrays forward on the next synchronized update. A spiking network starts from a different assumption: silence carries information too. When a neuron has no event to report, it stays quiet. When enough input has arrived, it emits a brief event called a **spike**.

A spike event is a small message that says, "something reached firing level at this moment." The event has a time attached to it, so the message is more than a yes-or-no signal. If two neurons both spike once, the neuron that spikes earlier can carry a different meaning from the neuron that spikes later. The network is therefore computing over a pattern of events in time, rather than only over a set of continuously changing numerical values. This is the core shift: information can live in **when** spikes happen, **how often** they happen, and **which** neurons produce them.

A familiar activation value, such as `0.8`, represents strength as a number available during a network update. A spike represents strength through events distributed across time. If a bright pixel drives a neuron strongly, that neuron might spike sooner, or it might spike more often inside a time window. If a dimmer pixel drives the same neuron weakly, the neuron might spike later, spike fewer times, or remain silent during that window. The value has moved from "how large is the activation right now?" toward "what event pattern appeared over time?"

This gives timing a computational role. Suppose two input neurons watch two nearby points in a moving edge. If the left neuron spikes at `2 ms` and the right neuron spikes at `5 ms`, the order suggests motion from left to right. If the timing reverses, the same two locations suggest motion in the other direction. A continuous snapshot can represent both locations as active, but a spike train can represent the order in which the activity arrived. The network can use that order as part of the signal.

A beginner confusion often appears here: a spike can look like a crude binary pulse, so it may seem less expressive than a continuous activation. The expressiveness comes from the whole spike train. One spike at one time is simple; many neurons producing sparse events across a time window form a rich temporal pattern. A short silence after a spike, a burst of closely spaced spikes, or an early single spike can each carry different information. The network reads the event pattern, much like a listener hears rhythm in a drum sequence rather than treating every beat as the same isolated click.

The word **sparse** describes activity where only a small fraction of neurons fire at a given time. Sparse activity fits naturally with spikes because most neurons can remain silent unless their inputs push them to fire. In a continuous network, each step usually propagates many activation values through many operations. In a spiking network, computation is triggered by events. If no spike arrives at a downstream neuron, there may be little or nothing for that neuron to update. When a spike arrives, the receiving neuron adjusts its internal state and may eventually fire its own spike.

That internal state is often described as a **membrane potential**, a running level of accumulated input. You can picture it as a cup collecting drops of water. Each incoming spike adds a drop. Some of the level may fade over time, so old input gradually loses influence. When the level reaches a firing threshold, the neuron emits a spike and the event travels onward. The threshold gives the neuron a simple decision rule: accumulated evidence has become strong enough to announce an event.

This mechanism turns computation into a sequence of local reactions. A neuron waits, receives spike events, updates its accumulated level, and fires only when the threshold is reached. The whole network can therefore operate **asynchronously**, meaning different parts of the network can update when their own events arrive rather than marching through every layer in lockstep at every time step. The computation follows the data's timing. A quiet region of the input produces few events; an active changing region produces more events; downstream computation concentrates where activity occurs.

Rate coding and temporal coding are two simple ways to understand how spikes can carry input strength. In **rate coding**, a stronger input causes more spikes within a chosen time window. For example, if one neuron fires ten times while another fires twice over the same interval, the first neuron is representing a stronger input under a rate-based interpretation. In **temporal coding**, the exact spike time carries meaning. A stronger input may cause an earlier spike, so the network can read strength from latency: the delay between the beginning of the input window and the spike. These codes can also appear together, because a spike train has both count and timing.

**Question.** If a spiking neuron only sends brief events, where does the original input strength go?

**Answer.** Input strength is represented through the spike pattern. A stronger input can push the neuron to fire earlier, fire more often within a time window, or recruit more neurons into firing. The strength becomes distributed across event timing, spike count, and which neurons participate.

Event-driven computation also changes what counts as computational work. In a dense continuous update, activity values must be processed even when many of them change very little. In a spike-based update, a silent neuron contributes by staying silent, and a firing neuron creates a concrete event that triggers downstream updates. The amount of work becomes tied to the number of spikes and the length of the time window used to reach a decision. A network that reaches a decision with fewer spikes and a shorter window performs fewer event-triggered operations.

A simple interpretation helps connect the pieces. Imagine three door sensors feeding a small network: one watches motion near the handle, one watches the hinge side, and one watches the floor. If the handle sensor fires first, then the floor sensor fires shortly after, the event order may suggest a person entering. If the floor sensor fires repeatedly while the handle sensor stays quiet, the pattern may suggest movement nearby without door use. The network receives more than three activation magnitudes; it receives a timed story of what changed and when.

**Question.** Does sparse spiking mean the network ignores quiet parts of the input?

**Answer.** Quiet parts still influence the representation by producing silence during the time window. Silence tells downstream neurons that no firing threshold was reached there. The network's computation focuses on events while treating the absence of events as part of the temporal pattern.

A spiking network can be understood as a system that waits for meaningful changes, stores recent evidence in neuron states, and communicates only when evidence crosses a firing threshold. Spikes separate the representation from continuous activations by making information discrete, timed, and sparse. Timing becomes part of the message, silence becomes meaningful, and computation follows events rather than a fixed rhythm of dense updates.
