## Spikes, Timing, and Event-Driven Computation

Imagine a small camera-like sensor watching a hand gesture. For several milliseconds, much of the scene stays still: the wall remains the same color, the table does not move, and most pixels carry no new information. If a network processes the whole scene at every time step, it spends work repeatedly confirming that most of the input is unchanged. The previous ideas of activation, signal, and time step help explain the cost: an activation is a numerical response, a signal is what flows through the network, and a time step is one slice of processing time. A conventional dense computation updates many activations every slice. A spiking neural network changes the rhythm of computation by treating silence as part of the signal. When something meaningful happens, a neuron emits a brief event called a spike.

A spike event is a discrete pulse at a particular time. Instead of carrying information as a continuously changing value, a spiking neuron communicates by deciding whether to fire and when to fire. The timing is part of the message. If a sensor sees a sudden edge move across the scene, the neurons connected to that change may spike quickly. If the input is weak or steady, fewer spikes appear. The network can then spend computation where events occur, rather than spreading equal effort across every neuron at every moment.

A sequence of spikes from one neuron over time is called a spike train. You can picture it as a row of time marks: a mark appears when the neuron fires, and empty space appears when it stays quiet. The empty spaces are meaningful because they say, "there is no event here right now." In a gesture-recognition task, a fast hand movement might create a dense cluster of spikes over a short window, while a still hand might create only a few scattered spikes. The network reads both the number of spikes and their timing pattern. A cluster near the beginning of the window can mean something different from the same cluster near the end, because temporal order changes the interpretation of the signal.

One simple way to describe activity over a time window is the spike rate:
$$
R = \frac{N}{T}
$$
Here, $r$ is the spike rate, $N$ is the number of spikes observed, and $T$ is the length of the time window. This formula lets you compute how frequently a neuron or group of neurons fires during that window. If a neuron fires 5 times in 10 milliseconds, its rate is $5 / 10 = 0.5$ spikes per millisecond. That rate gives a coarse description of activity, like saying a drumbeat is fast or slow. The exact spike times give a finer description, like hearing the rhythm of the drumbeat rather than only counting the beats.

This distinction explains why event-driven computation changes what the network computes. A dense activation-based network often treats each layer as a transformation of values at a processing step. A spiking network treats computation as an unfolding process across time. Each spike can contribute to later activity, and the network's state evolves as events arrive. This evolving behavior is called temporal dynamics. "Temporal" means time-based, and "dynamics" means the internal state changes as the process unfolds. The network's answer can depend on when spikes arrive, how close together they arrive, and how activity accumulates across the input window.

A useful analogy is a quiet room with motion-sensitive lights. A regular timed system might check every lamp every second, whether anyone is moving or not. An event-driven system waits for motion signals. When a person walks through the room, only the relevant sensors trigger activity. When the room is empty, the system stays mostly quiet. A spiking network follows a similar logic: spikes trigger useful computation, and sparse activity reduces unnecessary work.

Sparse activity means that only a small fraction of possible spike events actually occurs. This sparsity is one of the main reasons SNNs can use less energy. If neurons calculate mainly when they fire, then fewer spikes usually mean fewer operations. The relationship is direct: a network producing 4,000 spikes per inference gives the hardware far fewer events to handle than one producing 20,000 spikes per inference. Energy measurements reflect this pattern. Dense ANN-style computation can reach about 200 mJ per inference, while converted SNNs can reduce this to around 20 mJ, surrogate-gradient SNNs to around 15 mJ, and STDP-based SNNs to around 5 mJ with much lower spike counts. The numbers show the practical meaning of sparse spike trains: when fewer events travel through the network, less computation is triggered.

Latency also changes under event-driven computation. Latency is the time between receiving an input and producing a response. In real-time settings such as gesture recognition, robotic control, auditory processing, and neuromorphic vision, a useful answer must arrive quickly enough to guide action. SNNs can respond in small time windows because spikes arrive as soon as relevant input changes occur. Reported SNN inference latencies can fall around 5-10 ms per sample on neuromorphic platforms, while CNN-style ANN processing often takes around 20-50 ms depending on model and hardware. Directly trained surrogate-gradient SNNs can reach about 10 ms with competitive accuracy, and STDP-based SNNs can stabilize under 15 ms in optimized settings. Converted SNNs may need longer simulation windows, around 20 ms, because they often approximate continuous activation values through spike rates over time.

**Question.** If fewer spikes usually mean less computation, should a spiking network always try to produce as few spikes as possible?

**Answer.** A spiking network needs enough spikes to carry the information required for the task. Too many spikes waste energy and increase computation, but too few spikes can leave the network without enough evidence to recognize the input. The useful goal is sparse but informative activity: spikes appear when they help represent a meaningful change, pattern, or timing relationship.

A beginner confusion often comes from thinking of a spike as a tiny version of an activation value. A spike is better understood as an event in time. One spike does not say "the activation is 0.73." It says "this neuron fired now." Over a time window, many such events can represent intensity, pattern, and timing. A brighter or stronger input may produce more spikes, earlier spikes, or a more organized spike train, depending on how the network is designed and trained. The computation lives in the pattern of events, not in a single continuously stored number.

**Question.** How can silence carry information in a spiking neural network?

**Answer.** Silence means no spike event occurred during a particular period. If the network is watching for changes, no spike can indicate that the input stayed weak, stable, or irrelevant for that neuron. The absence of events helps the network avoid unnecessary updates while preserving the time structure of the signal.

The mental model is a network that listens for meaningful changes instead of constantly refreshing every value. A spike is the basic event, a spike train is the time pattern of those events, sparse activity keeps computation concentrated where information appears, and temporal dynamics let the network use order and timing as part of the representation. Representing information as spikes therefore changes both the content of computation and its schedule: the network computes through event patterns across time, and it works most when the signal gives it something new to process.
