A single spiking neuron can already turn accumulated input into a spike, but a useful system needs many such neurons arranged so that a raw signal can become a decision. Imagine a small vision sensor watching a doorway. Most of the scene stays still, but a person moves across a few pixels. A conventional dense pass would repeatedly handle a whole grid of numbers. A spiking neural network organizes the same job around events: the changed pixels become spikes, those spikes travel through layers, and the network's answer grows over time as later neurons respond to earlier spikes.

An SNN architecture is the organized pathway that carries spike events from input to output. The word architecture means the arrangement of parts and the direction of information flow. In an ordinary neural network, it is natural to picture one forward pass: input values enter, layers transform those values, and output values appear. In an SNN, the better mental picture is a process unfolding across time. The input arrives as a spike train, meaning a sequence of discrete firing events. Each event has a time, and that time helps carry information. A strong stimulus might create many spikes, or it might create an early spike, depending on the encoding scheme. The layers then process those events by accumulating incoming spikes, firing when internal activity reaches a threshold, and passing new spikes forward.

The architecture begins with input encoding because many real signals arrive as continuous measurements. A microphone waveform, a camera image, or a sensor reading must be turned into events before spiking layers can use it. Rate coding represents stronger input by producing spikes more frequently. If one pixel is bright and another is dim, the bright pixel may fire more often during the observation window. Temporal coding represents information through the exact timing of spikes. A stronger or more urgent signal may fire earlier. In the doorway example, a moving edge might create a brief cluster of spikes at the pixels where brightness changed. The input layer is therefore a translator: it changes ordinary data into spike trains that can move through an event-based network.

*Conceptual architecture of SNN* *(p. 4)*

The diagram shows the SNN as a pipeline from encoded input spikes, through spiking neuron layers, toward an output decision. The useful thing to notice is the direction of time. The input does not become one fixed vector that instantly produces one fixed output. Instead, spikes enter over a time window, and each layer reacts as events arrive. A spiking layer receives a pattern of incoming spike times, integrates them inside its neurons, and emits a new pattern of spike times. The next layer receives those emitted spikes as its own input. The architecture therefore behaves like a chain of event transformations: raw signal becomes input spikes, input spikes become hidden spike patterns, hidden spike patterns become output spike patterns, and output spike patterns become a prediction or control signal.

A spiking layer is a group of spiking neurons that process events in parallel. Each neuron listens to spikes from earlier neurons through connections. A connection has a weight, which controls how strongly an incoming spike changes the receiving neuron's internal state. When several incoming spikes arrive close together, their effects can build up. When the internal state reaches a firing threshold, the neuron emits its own spike. That emitted spike becomes an event for the next layer. In a vision task, early spiking layers might respond to simple local changes such as edges or motion. Later layers can combine those event patterns into more task-specific patterns, such as the presence of a moving person near the doorway.

This creates a temporal processing pathway. Temporal means time-based, and pathway means the ordered route information follows through the network. The pathway matters because a spike has meaning partly through when it happens. Suppose two input neurons fire. If they fire almost together, a receiving neuron may accumulate their effects strongly enough to fire. If they fire far apart, the first effect may fade before the second arrives, so the receiving neuron may stay silent. The same two input neurons can therefore lead to different outcomes depending on their timing. A beginner often expects a spike to behave like a simple 1 in a list of zeros and ones. A better picture is a tiny timed signal that can combine with other timed signals. The architecture is built to preserve and transform those timing relationships as spikes move through layers.

**Question.** If spikes are only brief events, how can an SNN represent something stable, such as "this image contains a digit 7"?

**Answer.** Stability comes from patterns over a time window. The network does not need one spike to carry the whole answer. Many input neurons produce spike trains, hidden layers transform those trains, and output neurons collect evidence over time. If the output neuron associated with "7" fires earlier, more often, or more strongly across the window than competing output neurons, the network can decode that spike pattern as the decision "7."

The output part of the architecture performs decoding. Decoding means turning the final spike pattern into a form the task can use. In a classifier, each output neuron may correspond to a possible class. The network can choose the class whose output neuron fires the most during a window, fires first, or accumulates the strongest evidence. In a control system, the output spikes may become an action signal, such as "turn left," "slow down," or "trigger an alert." The decision is therefore made over time. Early spikes can give a quick preliminary answer, while later spikes can add evidence. This is why latency, the time between input stimulus and response, becomes a natural performance measure for SNNs. A useful architecture should reach a decision with enough evidence while using as few spikes and as little time as the task allows.

The same architecture also explains why SNNs are associated with sparse event-driven computation. Sparse means that only a small fraction of neurons fire at a given time. Event-driven means computation is tied to spike events. If no relevant spikes arrive, many neurons have little or nothing to update. In the doorway sensor, a still background can remain mostly quiet, while motion produces a focused stream of events. The spiking layers then spend their effort where changes occur. This fits the architectural flow: encoded spikes enter only when the input produces events, hidden layers fire only when their thresholds are reached, and output decisions form from the spikes that actually occur.

**Question.** Does an SNN make its decision only at the final instant of the time window?

**Answer.** The output can be interpreted throughout the window. Early output spikes may already indicate a likely answer, and later spikes can strengthen or revise that answer. A system designer chooses a decoding rule that matches the task: count spikes across the whole window for a steadier decision, use the first output spike for a fast response, or use accumulated output activity when both speed and reliability are needed.

The full mental model is a timed chain of event processing. Input encoding turns ordinary signals into spike trains. Spiking layers receive those timed events, accumulate their effects, and emit new timed events. The temporal pathway carries patterns forward so that timing and frequency can both shape the computation. Output decoding reads the final spike activity as a decision, prediction, or control signal. An SNN architecture is therefore best understood as a living sequence of events flowing through layers, where silence, spike timing, and accumulated evidence all participate in the computation.
