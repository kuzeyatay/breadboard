## Inference Latency

Once a model's predictions can be checked for correctness, another practical question follows: how long does the model take to produce each decision? Imagine presenting a spiking neural network with a gesture signal. The input begins arriving, spikes travel through the network, and the output is eventually decoded into a predicted gesture. Measuring the duration of that journey gives the model's **inference latency**.

Inference is the phase in which a trained model uses a new input to produce a prediction, decision, or control signal. A correctness measure tells us how often those predictions match the expected answers. Inference latency describes their timing. Together, these measurements distinguish a model that answers accurately from one that answers accurately within the available time.

A latency measurement needs two clearly defined moments. The **input-stimulus time** is the time at which the input begins. We represent it by $t_{\text{stimulus}}$. For a picture presented all at once, this could be the moment the picture becomes available to the model. For an event-based gesture or an auditory signal, it could be the arrival time of the first event belonging to the sample. Whatever boundary is chosen, it must be applied consistently across all measured samples.

The **decision time** is the time at which the model produces its usable response. We represent it by $t_{\text{decision}}$. A response becomes usable when the model's output has been decoded into the decision required by the task. In a classification problem, that moment might occur when the output layer supplies the predicted class. The complete path therefore includes the input's arrival, input encoding when required, spiking-neuron processing, and output decoding into a prediction.

These two timestamps allow elapsed inference time to be derived directly. Time begins at $t_{\text{stimulus}}$ and ends at $t_{\text{decision}}$. Subtracting the starting time from the ending time leaves the duration between them:
$$
L = t_{\text{decision}} - t_{\text{stimulus}}
$$
Here, $L$ is the **inference latency**, $t_{\text{decision}}$ is the time when the model's decision becomes available, and $t_{\text{stimulus}}$ is the time when the input stimulus begins. If both timestamps are measured in milliseconds, then $L$ is also measured in milliseconds. The formula computes how much time passes from the start of an input to the resulting model decision.

Suppose a gesture stimulus begins at $125.0\ \text{ms}$, and the network's decoded prediction becomes available at $133.5\ \text{ms}$. Its inference latency for that sample is
$$
L = 133.5\ \text{ms} - 125.0\ \text{ms} = 8.5\ \text{ms}
$$
The absolute clock readings, $125.0\ \text{ms}$ and $133.5\ \text{ms}$, identify moments on a timeline. Their difference, $8.5\ \text{ms}$, describes the duration of inference. Starting the same process later would change both timestamps while preserving the latency if the model took the same amount of time. For example, a stimulus beginning at $400.0\ \text{ms}$ and a decision appearing at $408.5\ \text{ms}$ would again have a latency of $8.5\ \text{ms}$.

The start and end boundaries deserve careful attention because inconsistent boundaries produce misleading measurements. If one measurement begins when raw input reaches the system while another begins after input encoding has finished, the two latencies cover different portions of the inference pipeline. The same issue appears at the endpoint: timing one sample until spiking activity reaches the output layer and another until that activity has been decoded into a class compares different events. A useful measurement protocol states exactly what starts the clock and exactly what stops it.

A beginner may also confuse a model's number of processing timesteps with elapsed physical time. A timestep is a unit used to organize the model's temporal processing, while latency is measured between real start and decision timestamps. Their relationship depends on how the processing is executed. Consequently, physical latency should be obtained from the defined timing interval rather than inferred from the timestep count alone.

Latency can vary from one sample to another, especially when inputs unfold over time. Measuring several samples therefore produces a collection of values:
$$
L_i = t_{\text{decision},i} - t_{\text{stimulus},i}
$$
Where $i$ identifies a particular sample, $L_i$ is that sample's latency, $t_{\text{stimulus},i}$ is its input-stimulus time, and $t_{\text{decision},i}$ is its decision time. These per-sample measurements preserve the direct meaning of latency: each value records how long one input waited for one usable response. Any later aggregate should be built from measurements that share the same start condition, end condition, and time unit.

**Question.** If the model predicts the wrong class, does that sample still have an inference latency?

**Answer.** Yes. The model still produced a decision at a measurable time, so $t_{\text{decision}}-t_{\text{stimulus}}$ still gives its latency. Correctness and latency answer separate questions: one checks whether the decision matches the expected answer, while the other measures how long the decision took. Evaluating both reveals whether responses are accurate and timely.

**Question.** When an input arrives as a stream of events, which event should define the input-stimulus time?

**Answer.** The measurement protocol should choose a reproducible boundary, such as the first event belonging to the sample. Every sample must use that same rule. This makes $t_{\text{stimulus}}$ comparable across the evaluation and ensures that each measured interval begins at the same conceptual stage.

The resulting mental model is a simple timeline. An input begins at $t_{\text{stimulus}}$, moves through the inference pipeline, and becomes a usable decision at $t_{\text{decision}}$. Inference latency is the length of the interval connecting those moments. Clear boundaries turn that interval into a dependable measurement of how quickly a model responds.
