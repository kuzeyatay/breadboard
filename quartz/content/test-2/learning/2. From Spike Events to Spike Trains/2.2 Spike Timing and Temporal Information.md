A spike train gives an SNN more than a record of which neurons became active. It also records *when* each neuron became active. Because computation proceeds asynchronously, each spike arrives as an event at its own time rather than waiting for every neuron to update together. The resulting pattern unfolds like a rhythm: the identity of the spiking neuron tells the network where activity occurred, while the spike's arrival time tells it how that activity developed.

Imagine several sensors observing a moving object. One sensor responds as the object enters its region, another responds a few milliseconds later, and a third responds after that. The three sensors may each emit one spike, so their spike counts are identical. Their ordered firing times still reveal motion across the sensor array. Reversing the order of those same spikes suggests motion in the opposite direction. The network therefore needs both the active locations and the temporal order of their activity.

This combination is called **spatiotemporal information**. The *spatial* part identifies which input channels or neurons fired. The *temporal* part describes when they fired and how their events were ordered. A spike pattern can therefore be understood as a set of events distributed across neurons and time. Two patterns may activate the same neurons yet carry different information because their timing differs.

Consider three neurons named A, B, and C. Suppose they fire in the order A at 2 milliseconds, B at 5 milliseconds, and C at 8 milliseconds. That pattern could represent an event moving from A's receptive region toward C's. If C fires at 2 milliseconds, B at 5 milliseconds, and A at 8 milliseconds, the spatial participation remains the same, but the temporal sequence changes. A downstream spiking neuron receives these events in a different order and can consequently produce a different response.

Using changes over time as part of computation is called **temporal processing**. An SNN performs temporal processing when its response depends on spike timing, spike order, or spike frequency across an interval. Timing can carry information in more than one way. In **temporal coding**, the exact arrival time of a spike carries meaning. An earlier spike might indicate a stronger or more immediate input, while a later spike might indicate a weaker or delayed one. In **rate coding**, meaning is carried by how frequently spikes occur: a stronger input can produce more spikes during the observed interval.

Suppose one input neuron emits five spikes while another emits two during the same period. Under a rate code, the first input represents greater intensity because its firing frequency is higher. Now suppose each input emits exactly one spike, but the first fires at 3 milliseconds and the second at 12 milliseconds. Under a temporal code, the difference in arrival time can distinguish the inputs even though their spike counts match. Rate coding asks, "How many spikes arrived during the interval?" Temporal coding asks, "At what times did the spikes arrive?"

Timing also determines how events from different neurons interact during processing. A spiking neuron receives events from many incoming connections. Events arriving close together can create a concentrated input pattern, while widely separated events create a more dispersed pattern. The same collection of incoming spikes can therefore have different effects when their spacing changes. A cluster arriving over a short period may drive a rapid response; the same spikes spread across a longer period may produce a later or weaker response. The useful signal lies in the pattern's shape over time.

**Question.** If two spike trains contain the same number of spikes, can they represent different information?

**Answer.** Yes. Spike count captures frequency within an interval, but it does not fully describe timing. One train might contain spikes at 2, 4, and 6 milliseconds, while another contains spikes at 2, 10, and 18 milliseconds. Both contain three spikes, yet the first forms a compact burst and the second forms a dispersed sequence. A temporally sensitive network can respond differently to these patterns because their event spacing and duration differ.

To interpret a spike train, an SNN observes activity over a finite **simulation window**. A simulation window is the span of time during which spikes are generated, processed, and collected for one inference or computational episode. For example, a network might observe incoming events from 0 to 10 milliseconds and then decode the resulting spike pattern into a decision. The window establishes which events belong to that decision and how much temporal evidence the network can gather.

Window length affects the information available to the network. A longer window allows more spikes to occur, which can make firing-rate estimates clearer and give delayed events time to influence the output. It also extends the time required to finish processing. A shorter window can produce a decision sooner and may involve fewer spikes, while offering less time to accumulate evidence. Some converted SNNs require higher spike counts and longer simulation windows because their information is conveyed through repeated rate-coded spikes. Other learned spiking patterns can reach useful outputs with fewer events or lower latency.

Imagine estimating input intensity by counting spikes. During a 2-millisecond window, one neuron emits one spike and another emits none. That small sample gives a rough comparison. During a 20-millisecond window, the neurons emit ten and four spikes respectively, making their relative rates easier to distinguish. The longer observation provides more evidence, while the shorter observation supports an earlier response. Choosing a simulation window therefore links representation, latency, and spike count.

The output must eventually translate the temporal pattern into a usable result. After input encoding converts audio, images, or sensor measurements into spike trains, layers of spiking neurons process the timing and intensity of those events. An output stage then decodes the resulting pattern into a prediction, decision, or control signal. Decoding may use spike counts accumulated within the window, the timing of an output spike, or the pattern formed across several output neurons.

**Question.** Does an early spike always mean a stronger input?

**Answer.** Its meaning depends on the encoding scheme used by the network. In a temporal code designed around response latency, earlier firing may represent greater intensity. In a rate code, intensity is represented by spike frequency across the simulation window, so one early spike provides only part of the evidence. Spike timing gains meaning through the rule that maps input values to spike trains and the rule that decodes output activity.

A useful mental model is to picture an SNN listening to a timed conversation among neurons. Each speaker's identity supplies the spatial information, each utterance's time supplies the temporal information, and the simulation window sets the portion of the conversation used for a decision. Temporal processing follows the order, spacing, and frequency of those utterances. Through that combined spatiotemporal pattern, a spike train carries both what happened across the network and how it unfolded in time.
