## Latency Comparisons Across Models

After seeing that spiking models can trade accuracy, energy use, spike count, and convergence behavior in different ways, latency gives us the timing side of the same design choice. Imagine a hand-gesture sensor on a small robot. The camera-like event sensor detects motion, the model must classify the gesture, and the robot must react while the motion is still relevant. If the model waits too long before deciding, even an accurate answer can arrive too late to guide the next action. Latency is the time between receiving an input and producing a usable decision. In these results, latency is measured in milliseconds, abbreviated ms, where 1 millisecond is one thousandth of a second.

A latency comparison asks a practical question: how quickly does each model respond under the same kind of inference task? The model with the lower latency value gives its answer sooner. A response around 10 ms means the system can, in principle, make about one decision within a hundredth of a second. A response around 50 ms takes five times as long. For a desktop classifier looking at stored images, that difference may feel small. For an edge device reacting to a gesture, a sound, or a fast-changing sensor stream, those extra milliseconds can determine whether the model feels immediate or sluggish.

The comparison includes four model families: a conventional ANN/CNN, a converted SNN, a surrogate gradient SNN, and an STDP-based SNN. The ANN/CNN represents a dense artificial neural network approach, where information usually flows through layers as continuous numerical activations. The converted SNN begins with an ANN-like model and translates its behavior into spikes, often by using spike rates over a simulation window to approximate the original continuous activations. The surrogate gradient SNN is trained directly as a spiking model, using a learning trick that lets gradient-based optimization handle spike events. The STDP-based SNN uses spike-timing dependent plasticity, where connection strengths adapt from the relative timing of pre-synaptic and post-synaptic spikes.

Those training differences matter because a spiking model often needs time to collect enough spike activity before it can make a confident decision. A converted SNN may require a longer simulation window because it is trying to reproduce the strength of an ANN activation through the number or rate of spikes. If a high activation is represented by many spikes, the model may need to wait long enough for the rate pattern to become clear. A directly trained surrogate gradient SNN can learn spike patterns that support earlier decisions, because training has shaped the spiking dynamics themselves rather than relying only on a conversion from continuous activations.

The table turns the timing comparison into specific numbers. The ANN/CNN sits in the higher-latency range, roughly 20-50 ms depending on model and hardware conditions. The converted SNN is shown around 20 ms, which is faster than many conventional CNN cases but still slower than the best directly trained spiking option in this comparison. The surrogate gradient SNN reaches about 10 ms, placing it in the low-latency range while still preserving competitive accuracy from the broader results. The STDP-based SNN can stabilize below about 15 ms under optimized conditions, which is also fast, though its early inference behavior can be slower because adaptation unfolds gradually through spike timing.

A useful way to read the table is to treat each millisecond value as a waiting cost. If a sensor produces an event and the model needs 10 ms to respond, the system waits through a very short decision window. If another model needs 20 ms, it waits twice as long. The difference between 10 ms and 20 ms may sound tiny in everyday time, but it is large for systems that repeatedly sense, decide, and act. A robot running a perception loop, a wearable device detecting motion, or a neuromorphic chip processing event streams may perform many such decisions per second, so the per-sample delay accumulates into a different user experience and a different control behavior.

The latency result supports a specific model-selection rule. When the goal is fast response with strong accuracy, the surrogate gradient SNN is the best aligned choice among the compared SNN training approaches. It directly learns spiking behavior, reaches low latency around 10 ms, and remains close to ANN-level accuracy in the broader performance picture. Converted SNNs remain useful when an existing ANN must be reused, but the conversion can carry a timing cost because the spiking version may need more time steps to represent the original activation values. STDP-based SNNs fit especially well when sparse activity and low energy are the central goals, and their sub-15 ms stabilized latency keeps them relevant for efficient systems, but the low-latency accuracy target points most clearly to surrogate gradient training.

**Question.** If STDP-based SNNs can reach sub-15 ms latency, why choose a surrogate gradient SNN for low-latency applications?

**Answer.** A low-latency application usually needs speed together with reliable task accuracy. The surrogate gradient SNN reaches about 10 ms and is trained directly to produce useful spiking decisions with competitive accuracy. STDP-based SNNs can become very fast after optimization and are especially attractive for low-energy sparse spiking, but their gradual spike adaptation and accuracy behavior make them less directly matched to a low-latency accuracy target.

A common beginner confusion is to read latency as a property of the model name alone, as if every SNN automatically responds faster than every ANN. The better picture is that latency depends on how the model represents information over time. Spikes can enable fast event-driven decisions, but a spiking model that waits for a long rate-coded window may lose some of that timing advantage. A converted SNN can inherit this issue because it often represents activation strength through spike counts across time. A surrogate gradient SNN can learn to use spike timing more directly, so the decision can emerge from a shorter window.

**Question.** Does a lower latency value always mean the model is the best overall choice?

**Answer.** A lower latency value means the model responds faster for the measured inference setting. Overall model choice also depends on accuracy, energy consumption, spike count, convergence behavior, and the application's constraints. For low-latency response with competitive accuracy, the surrogate gradient SNN is the strongest match in these results. For ultra-low-power operation, an STDP-based SNN may become more attractive even if the selection goal changes.

The mental model is to picture each architecture as asking for a different amount of evidence before it speaks. A conventional ANN/CNN processes dense numerical activity and can take tens of milliseconds. A converted SNN listens to spikes long enough to estimate activation rates, which can lengthen the decision window. An STDP-based SNN learns from spike timing and can become fast after its activity stabilizes. A surrogate gradient SNN is trained so that its spikes carry decision-useful information quickly, giving it the clearest fit when the system needs a fast answer and still cares about accuracy.
