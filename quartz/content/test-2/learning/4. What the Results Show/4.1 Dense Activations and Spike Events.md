### Dense Activations and Spike Events

Once a neuron layer has an activation at each time step, there are two very different ways the layer can carry information forward. Imagine a camera sensor looking at a quiet hallway. Most pixels barely change from one moment to the next, but a dense neural network still turns the whole image into arrays of numbers, pushes those numbers through matrix operations, and produces a fresh set of activations for the next layer. Every neuron in the layer participates by holding a continuous value such as `0.13`, `2.7`, or `-0.04`. A spiking system starts from a different assumption: silence can carry meaning. If the hallway is still, most neurons stay quiet. When something changes enough to matter, a neuron emits a brief event at a particular moment. That event is a spike.

A continuous-valued activation is information stored as a numerical magnitude. In an ordinary artificial neural network, a neuron receives inputs, combines them, applies an activation rule, and passes a real-valued output to the next layer. The value itself carries the message. A larger activation can mean stronger evidence for a feature, such as an edge in an image or a sound pattern in audio. Because each layer usually computes a full array of activations, the computation is dense: many values are updated together, even if only a small part of the input has changed. This style is powerful because it gives every layer a smooth numerical surface to work with, but it also means inference often depends on large matrix multiplications and continuous propagation of values from layer to layer.

A binary spike event carries information in a more compressed form. A neuron either fires at a time step or stays silent. The spike can be represented as `1`, while silence can be represented as `0`. At a single moment, that looks almost too simple: one bit instead of a continuous number. The missing richness comes back through time. A neuron can fire early, fire late, fire often, fire rarely, or fire in a pattern with other neurons. The message is distributed across events. A bright or strong input may cause frequent spikes in rate coding, where input strength is represented by spike frequency. A sudden or urgent signal may be represented by temporal coding, where the exact timing of a spike carries the information. In both cases, the spike is the visible event, and the timing of events becomes part of the representation.

A useful analogy is a group chat. A dense activation layer is like every person sending a status update every minute, even when their status has not changed much. A spiking layer is like people sending a message only when something happens. If one person says nothing, that silence is part of the communication pattern. If several people message at nearly the same time, the timing itself tells you that their observations are related. A spike train is the sequence of spikes emitted by one neuron or a group of neurons over time. For one neuron, a spike train might look like silence for three time steps, then a spike, then more silence, then two closely spaced spikes. For a layer, many spike trains run side by side, forming a time-based pattern of activity.

This difference changes how computation happens. In a dense network, a layer update usually means recomputing many activation values together. Even a small change in input can trigger a full pass through the same numerical machinery. In a spiking network, activity is event-driven. A neuron update becomes necessary when spikes arrive or when its internal state has accumulated enough evidence to fire. This is called an asynchronous update: different neurons can update at different times because the computation follows events rather than a single global rhythm where every unit must produce a fresh continuous value at every step. Time steps can still be used to simulate the system, but the meaningful work is concentrated around the moments when spikes occur.

This event-driven style explains why spike count is tied to energy use. If computation happens mainly when spikes occur, then fewer spikes usually mean fewer operations. Dense artificial networks can consume much more energy because continuous-valued operations keep many units active. Reported comparisons show a dense ANN around `200 mJ` per inference, while spike-based models can be far lower: a converted SNN around `20 mJ`, a surrogate-gradient SNN around `15 mJ`, and an STDP-based SNN around `5 mJ`. The spike counts follow the same pattern of sparsity: converted SNNs may use roughly `20,000` spikes per inference, surrogate-gradient SNNs around `12,000`, and STDP-based SNNs around `4,000`. These numbers give a concrete interpretation of "event-driven": the system saves work because most neurons do not need to keep announcing a new value when they have no event to send.

**Question.** If a spike is only a `1` and silence is only a `0`, how can a spiking network represent detailed information?

**Answer.** The detail comes from patterns over time and across neurons. One spike at one moment is simple, but a spike train can encode strength through frequency, timing through exact spike positions, and relationships through which neurons fire together. A continuous activation stores information mainly in the size of a number at one computation step. A spiking representation spreads information across event timing, event frequency, and population patterns.

The same input can therefore be expressed in two different languages. Suppose a sensor detects a stronger signal. A dense layer may represent that signal as a larger activation value, such as moving from `0.2` to `0.8`. A rate-coded spiking layer may represent the stronger signal by producing more spikes within the same window of time. A temporally coded spiking layer may represent it by firing sooner. These are different encodings of intensity. The dense version says, "the value is larger." The spiking version says, "events are more frequent," or "the event happened earlier." Once that idea is clear, a spike train becomes less mysterious: it is a time-shaped code for information.

There is a beginner confusion that often appears here: silence can feel like absence of computation, so it may seem as if the network has lost information whenever neurons do not fire. In a spiking system, silence is part of the code because it tells later neurons that no event has crossed the firing condition during that period. A quiet neuron can mean weak input, already-settled evidence, or no relevant change. The meaning depends on the coding scheme and the surrounding spike trains. The system is designed so that useful information appears in the pattern of events and non-events over time.

**Question.** Does an asynchronous spiking network ignore time steps completely?

**Answer.** Time steps can still be used to organize simulation or measurement, but the computation is driven by spike arrivals and firing events. In a dense network, every step often means a broad update of continuous activations. In a spiking network, the useful updates cluster around moments when events occur, so different neurons can become active at different times.

This is the mental model to carry forward: continuous neural computation treats each layer as a field of values that must be refreshed and propagated, while spike-based computation treats each layer as a population of event senders whose silence and firing times both carry meaning. Dense activations describe "how much" using numerical magnitude. Spike trains describe "when" and "how often" using events over time. That shift from always-updated values to sparse temporal events is what makes spiking neural networks naturally suited to time-varying signals and energy-constrained hardware.
