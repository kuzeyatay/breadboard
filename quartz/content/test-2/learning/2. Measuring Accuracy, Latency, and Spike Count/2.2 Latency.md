After measuring whether a model chooses the right answer, the next natural question is how long the model takes to choose it. Imagine a hand-gesture sensor controlling a small robot. The sensor receives a new gesture at a particular moment, and the robot waits for the model to decide what that gesture means. If the answer arrives quickly, the robot can react while the gesture is still relevant. If the answer arrives too late, even a correct classification can feel unusable in a real-time system, because the world has already moved on.

Latency names this time cost of a decision. It measures the delay between the moment an input stimulus arrives and the moment the model produces its decision. An input stimulus is the signal being presented to the model, such as a gesture event stream, an audio pattern, or an image sample. The decision time is the moment when the model has enough output evidence to commit to a class or action. The difference between those two times is the decision delay, and that delay is the latency.

The metric can be written directly:
$$
\text{Latency} = t_{\text{decision}} - t_{\text{stimulus}}
$$
Here, $t_{\text{stimulus}}$ is the time when the input stimulus begins or is made available to the model, $t_{\text{decision}}$ is the time when the model produces its decision, and latency is the elapsed time between them. When these times are measured in milliseconds, abbreviated ms, the result tells you how many thousandths of a second the model needed. For example, if a gesture begins at $0$ ms and the model decides at $10$ ms, then the latency is $10 - 0 = 10$ ms. If another model decides at $20$ ms for the same input timing, its latency is $20$ ms. The lower number means the decision arrives sooner.

This formula is simple because latency follows from measurable counts of time. You do not need to know the internal weights of the model to compute it. You need a start marker for the stimulus and an end marker for the decision. That makes latency useful when comparing very different systems, such as a conventional artificial neural network and several spiking neural network designs. Their internal computation may be organized differently, but each one can still be asked the same practical question: after the input arrives, when does the answer appear?

A spiking neural network makes this metric especially natural because its computation unfolds over time. Instead of passing only continuous values through layers, it communicates with discrete spike events. A spike is a brief event that occurs at a particular time, so the timing of activity is part of the computation. The model may need to observe enough spikes across a simulation window before the output becomes clear. A simulation window is the span of model time allowed for spikes to accumulate and influence the decision. If the window is longer, the model may have more time to approximate a stable answer, but the decision can arrive later. If the model learns to use earlier spikes more effectively, the decision can arrive sooner.

Converted SNNs show why the simulation window matters. A converted SNN begins from an ANN-style model and translates its continuous activations into spiking behavior. Because continuous activation levels often need to be approximated by spike rates over time, the converted model may require a longer window before the spike pattern represents the original activation reliably. That longer window can increase latency. In a real-time setting, this feels like waiting for enough votes to arrive before announcing the winner: the final decision may be good, but the waiting period is part of the cost.

Surrogate gradient SNNs offer a different timing picture. They are trained directly around spiking behavior using a learning method that can shape when spikes occur. When the model learns spike timing patterns that support early decisions, latency can fall. A reported latency around $10$ ms means the model can often turn an input into a decision within ten thousandths of a second. That number should be read as a time-to-answer measure, not merely as a speed label. A $10$ ms model leaves more time for the rest of a real-time system to act than a $20$ ms model does.

**Question.** If two models have the same accuracy, should the lower-latency model always be preferred?

**Answer.** Lower latency is better when the decision must be used quickly, such as in edge AI or real-time robotics. A lower-latency model gives the system an answer sooner. The choice still depends on the full set of metrics, because a model may trade latency against accuracy, energy use, spike count, or training behavior. Latency answers the time-cost question, not every performance question at once.

Latency also has a useful discipline: it moves only when its inputs move. In the formula, latency changes if the stimulus time changes, the decision time changes, or the way those two moments are measured changes. If the stimulus begins at $5$ ms and the decision arrives at $15$ ms, the latency is still $10$ ms. Shifting both times forward by the same amount leaves the delay unchanged. If the decision moves earlier to $12$ ms while the stimulus remains at $5$ ms, latency becomes $7$ ms. This is why latency measures elapsed decision time rather than absolute clock position.

A beginner confusion often comes from mixing latency with accuracy. Accuracy asks whether the decision is correct. Latency asks when the decision arrives. A model can be accurate but slow, fast but less accurate, or balanced between the two. In spiking systems, this distinction becomes practical because waiting for more spikes can sometimes strengthen confidence, while deciding earlier can reduce delay. The latency metric gives a clean way to talk about that time choice without hiding it inside the accuracy number.

**Question.** Why does a longer simulation window usually increase latency?

**Answer.** A longer simulation window gives the spiking model more time steps in which spikes can occur and influence the output. If the decision is made after that window, or after enough activity accumulates inside it, extending the window can push the decision later. Converted SNNs often need this extra time because they approximate continuous ANN activations through spike activity spread across time.

A good mental model is to picture latency as the stopwatch wrapped around a decision. The stopwatch starts when the stimulus arrives. It stops when the model commits to an output. Spiking models make the stopwatch especially meaningful because spikes unfold in time, and different training strategies shape how quickly useful spike evidence appears. Converted SNNs may wait longer to gather rate-based evidence, surrogate gradient SNNs can learn fast spike patterns, and STDP-based SNNs can reach low delays while adapting through spike timing. Latency turns all of that temporal behavior into one interpretable measurement: the time cost paid before a decision can be used.
