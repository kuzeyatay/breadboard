## Rate, Latency, and Delta Spike Encoding

A spike train gives us a sequence of event times, while a time-varying signal gives us a value at each moment. Connecting these two representations requires an **encoding rule**: a procedure that decides when the signal should produce spikes and what those spikes mean. Imagine that a sensor reports brightness on a scale from dark to bright. The sensor produces real-valued measurements, perhaps 0.2, 0.7, or 0.9, but a spiking network receives discrete events. Spike encoding translates those measurements into patterns of spikes while preserving the information needed for later computation.

Different encoding rules preserve different aspects of the signal. **Rate coding** represents magnitude through the number or frequency of spikes. **Latency coding** represents magnitude through the time at which a spike occurs. **Delta modulation** represents changes in the signal by producing events when the value moves sufficiently upward or downward. The same brightness trace can therefore become three very different spike trains because each rule answers a different question: "How large is the value?", "How quickly should the value announce itself?", or "How has the value changed?"

Consider a signal held near a constant value during a short observation window. A rate encoder converts that value into a firing rate, meaning the number of spikes produced per unit of time. A larger input produces more spikes during the window, while a smaller input produces fewer. If brightness 0.8 generates eight spikes in a chosen interval and brightness 0.3 generates three, the receiving system can estimate brightness by counting spikes. The exact timing of each individual spike carries less emphasis than the accumulated count across the interval.

This creates a natural averaging process. One spike arriving slightly earlier or later has limited influence when the receiver uses the total number of spikes. The estimate becomes clearer as more time is available for counting. That same dependence on a counting interval creates an encoding trade-off: a longer interval can provide a more stable rate estimate, while a shorter interval can deliver information sooner. Rate coding therefore represents magnitude through repeated evidence gathered over time.

A simple way to think about rate coding is to imagine rainfall collected in a measuring cup. A heavy rain produces many drops during one minute; a light rain produces only a few. Any single drop reveals little, but the number of drops accumulated during the minute indicates the rainfall intensity. In a rate-coded spike train, each spike acts like one drop, and the spike count over the observation window represents the signal's magnitude.

Latency coding places the information in a different feature of the spike train. The encoder begins from a reference time, such as the start of a presentation window, and the input value determines the delay before a spike appears. A stronger value is commonly represented by an earlier spike, while a weaker value is represented by a later one. The receiver reads the delay, called **latency**, instead of waiting to count many events.

Suppose two sensor values begin encoding at the same instant. A high brightness value produces a spike after 2 milliseconds, while a lower brightness value produces one after 8 milliseconds. The earlier spike communicates the stronger input. In this representation, a single event can carry information through its position in time. Accurate interpretation therefore depends on a shared temporal reference: the receiver needs to know when the encoding interval began so that it can measure the delay.

Latency coding resembles runners leaving the same starting line. Their arrival order and arrival times reveal differences in speed. An early arrival indicates a strong response, and a later arrival indicates a weaker response. Because the message can be conveyed by the first spike, latency coding can communicate a value without accumulating a long spike count. Its precision depends on how finely the system can distinguish spike times and how reliably the reference time is established.

Delta modulation shifts attention away from the signal's current level and toward its movement. The word **delta** means change. The encoder compares the current signal with a tracked reference value and emits a spike when the difference becomes large enough to register. An upward change can produce one kind of event, while a downward change can produce another. Each event updates the represented value in the corresponding direction.

Imagine that brightness remains at 0.5 for several moments, rises to 0.7, stays there, and then falls to 0.4. Delta modulation concentrates spikes around the rise and fall. During the flat portions, the signal produces little or no event activity because its value remains stable. The receiver interprets the events as instructions such as "increase the reconstructed value" or "decrease the reconstructed value." A sequence of these updates allows it to follow the changing signal.

Read each row by asking what feature of the spikes follows the real-valued input. In rate coding, larger values correspond to denser spike activity, so information appears in spike count or firing frequency. In latency coding, the decisive feature is the first-spike time relative to a reference: earlier and later spikes represent different magnitudes. In delta modulation, spikes cluster where the input changes, and their direction tracks increases or decreases. Flat signal regions can therefore look active under rate coding, produce a value-dependent timed event under latency coding, and remain quiet under delta modulation. The shapes differ because the encoders preserve different information.

**Question.** If rate coding and latency coding both represent signal magnitude, why do their spike trains look so different?

**Answer.** They assign magnitude to different measurable properties. Rate coding maps magnitude to the number of spikes observed during an interval. Latency coding maps magnitude to the delay before a spike occurs. A strong input can therefore appear as many spikes in one encoding and as one early spike in the other. The receiver must apply the same interpretation rule used by the encoder.

A common beginner confusion arises when silence appears in a delta-modulated spike train. Silence represents a period without a sufficiently large change. A high but steady signal can remain quiet because its level has already been established by earlier events. Rate coding would continue producing spikes for that same steady high value because its activity represents level rather than change.

**Question.** Can a spike count, an early spike, and a change event all mean "the input is large"?

**Answer.** A large spike count directly represents a large value under rate coding, and an early spike can represent a large value under latency coding. A delta event represents movement in the value. Several upward delta events can build toward a large reconstructed level, but each event communicates an increment rather than the complete magnitude by itself.

The three encodings can be held together in one mental model. Rate coding asks the receiver to count activity, latency coding asks it to measure waiting time, and delta modulation asks it to accumulate changes. Counting favors repeated evidence about level, timing places value into the position of an event, and change events concentrate activity around movement in the signal. Choosing among them means deciding which feature of the original signal should become easiest to read from the resulting spike train.
