## Rate, Latency, and Delta-Modulation Encoding

A spike train gives us a sequence of discrete events in time, but conventional data often arrives in another form: an image supplies pixel intensities, a microphone supplies a changing signal, and a sensor may report a numerical measurement at regular intervals. Before a spiking neural network can process such values, an **encoder** must translate them into spikes. The encoder decides which feature of the original input will carry the message: its magnitude can control how many spikes occur, when the first spike occurs, or whether a change is large enough to deserve a new event.

Consider one grayscale pixel with an intensity between dark and bright. A conventional system can pass that intensity forward as a number. A spiking system needs to express the same information through events distributed across a processing interval. **Rate encoding** does this by making intensity control firing frequency. A bright pixel produces a spike train with a high firing rate, while a dim pixel produces a train with a low firing rate. If spikes are generated probabilistically, the pixel intensity can determine the rate of a Poisson spike train, so the exact spike times vary even when the underlying intensity stays fixed.

Suppose a bright pixel generates eight spikes during a chosen interval while a dim pixel generates two. The individual event times are less important than the accumulated count: eight spikes indicate stronger input than two. The receiving network can estimate the encoded intensity by counting spikes over that interval. This reconstruction step is **spike decoding**, the process of turning a spike-based representation into an interpretable output. For rate-coded activity, decoding commonly means counting events or measuring their average frequency.

Rate encoding provides repeated evidence about the same value. If one expected spike occurs slightly early, slightly late, or fails to appear, the remaining spikes still carry information about the intensity. This gives the representation relatively high tolerance to spike-level errors and supplies learning procedures with many events from which to adjust the network. The same repetition also requires time: a firing rate becomes dependable only after enough of the observation interval has passed to distinguish a genuinely high rate from a temporarily dense cluster of spikes. More spikes also mean more events must be processed.

**Latency encoding** compresses the message into the timing of a neuron's first spike. It is often called **time-to-first-spike**, or **TTFS**, encoding. Here, stimulus intensity and spike delay are negatively correlated: a stronger input produces an earlier spike, while a weaker input produces a later one. Each input neuron can therefore communicate its value with a single event during the encoding interval.

Imagine that the interval begins at time zero. A bright pixel might trigger its neuron near the beginning, while a dimmer pixel triggers its neuron closer to the end. A downstream neuron reads the relative arrival times and treats early arrivals as evidence of stronger stimulation. Decoding therefore converts first-spike time back into an intensity estimate or uses the order of arrivals directly. Because each neuron contributes one spike per input, the representation can use fewer events and complete its message sooner than rate encoding.

The timing must remain informative for latency decoding to work well. A small displacement in a first spike can change the estimated input more directly than the displacement of one event within a long rate-coded train. Rate encoding spreads evidence across several spikes; latency encoding concentrates evidence in one carefully timed spike. This tradeoff explains why rate coding can provide greater error tolerance and more spike activity for gradient-based learning, while latency coding can offer faster processing with lower event activity.

A third approach becomes natural when the input changes over time. Imagine a sensor watching a mostly steady signal. Repeatedly encoding the same value spends spikes on information the receiver already has. **Delta-modulation encoding** focuses on the difference between the current input and a reference value, where "delta" means change. When the signal rises far enough, the encoder emits an event representing an upward change. When it falls far enough, it emits an event representing a downward change. During nearly constant periods, the spike train becomes quiet.

For example, suppose a sensor value rises gradually from 20 to 23, stays near 23, and then drops to 21. A delta-modulation encoder can emit upward-change spikes during the rise, remain mostly silent on the plateau, and emit downward-change spikes during the fall. The decoder maintains a running estimate and updates it whenever an event arrives. Each upward event raises the estimate by the encoder's chosen change amount, and each downward event lowers it. The resulting spike train emphasizes motion or variation rather than repeatedly announcing the absolute level.

The three paths in the figure follow the same overall journey from conventional input, through a spike-based representation, into a decoded output. Their spike patterns preserve different aspects of the input. The rate path represents magnitude through the density or count of spikes. The latency path represents magnitude through the delay before the first spike, with stronger values appearing earlier. The delta-modulation path places events around changes, so transitions generate activity while stable regions generate little activity. The decoding side mirrors these choices: it counts rate-coded spikes, interprets first-spike timing, or accumulates signed changes to recover an evolving estimate.

**Question.** If rate and latency encoding begin with the same pixel intensity, do they produce equivalent spike trains?

**Answer.** They preserve the intensity through different measurable features. Rate encoding turns the intensity into an expected spike frequency, so decoding requires observing and counting several events. Latency encoding turns the intensity into a first-spike delay, so decoding reads when one event arrives. The represented input may be the same even though the spike trains have very different lengths and timing patterns.

**Question.** Why can delta-modulation encoding become quiet even while the sensor still has a nonzero value?

**Answer.** Its events describe changes from a maintained reference rather than repeatedly reporting the current magnitude. Once the decoder has reconstructed the present level, a stable signal requires no further update. New spikes appear when the input rises or falls enough to change that reconstruction.

The useful mental model is to treat spike encoding as a choice about where information lives. Rate encoding places it in repeated event counts, latency encoding places it in first-event timing, and delta modulation places it in event-triggering changes. Decoding reverses that choice by counting, timing, or accumulating. The appropriate representation follows the character of the input and the needs of processing: repeated spikes provide redundant evidence, a first spike communicates quickly, and change-driven events concentrate activity around a signal's movement.
