## Online and Event-Driven Learning Rules

Once spikes carry information through their count or timing, the network still needs a way to change its synaptic weights. Imagine a stream of sound arriving continuously at a spiking network. The network could record every membrane state and spike across a long interval, wait until the interval ends, and then use backpropagation through time (BPTT) to assign credit to earlier activity. That approach gives the learning process access to the full temporal sequence, but storing and revisiting all those states demands memory and computation. An online learning rule follows the stream as it arrives: spikes trigger updates during processing, allowing learning to proceed without repeatedly replaying an entire recorded sequence.

BPTT treats a spiking network as a dynamical system unfolded across time. Each time step becomes another stage in a long computational chain, so an error measured later can influence weights that affected earlier membrane states and spikes. Because spike generation contains a sharp threshold, gradient-based training commonly uses a surrogate gradient: a smooth approximation that supplies a usable learning signal near the threshold. This creates an optimization-oriented training method with broad access to the network's temporal behavior. It can coordinate changes across layers and across time because the final error is propagated backward through the unfolded computation.

Online learning changes when information is used. At time $t$, the network receives the current input events, updates its neuron states, produces any resulting spikes, and applies an available learning signal. The updated weights can then influence processing at time $t+1$. Learning and inference therefore advance together through the event stream. A spoken syllable offers a concrete picture: each incoming acoustic event modifies the active neuron states, and an online rule can adjust relevant connections while the sound is still unfolding rather than retaining the complete syllable for a later backward pass.

An event-driven update changes computation only when a relevant event occurs. If a presynaptic neuron emits a spike, the synapses leaving that neuron become candidates for processing. If no spike arrives, those synaptic operations can remain idle. Sparse spike trains therefore create sparse opportunities for both neural computation and learning. The same principle motivates event-driven SNN operation more generally: discrete spikes identify the places and times where work is needed.

A local learning rule further restricts the information available to each update. A synapse can use quantities present near its two connected neurons, such as their spike timing or activity, rather than receiving a precisely propagated derivative from distant layers and later time steps. Spike-timing-dependent plasticity (STDP) is the established example: the relative timing of presynaptic and postsynaptic spikes determines how a connection changes. Its update is naturally tied to events, and its required signals are available around the synapse. This gives STDP strong biological plausibility because learning can arise from temporally related neural activity through local synaptic changes.

Locality also limits credit assignment. Suppose an early neuron spikes, several intermediate neurons transform that event, and the final output is incorrect. BPTT can carry the output error backward through the intervening computations and estimate how the early weight contributed to the result. A local rule sees the activity near that early synapse. It can strengthen or weaken the connection according to nearby spike relationships, while the distant output error may remain unavailable. Biological plausibility and optimization practicality therefore emphasize different forms of information: local rules favor signals that a synapse could access during ongoing activity, whereas full temporal backpropagation favors coordinated adjustment using an explicit objective and stored temporal dependencies.

Rate and latency encoding shape these learning conditions. In rate encoding, a stronger input is represented by more spikes during a time window. Repeated spikes provide multiple events from which an update rule can gather evidence. This redundancy gives rate coding higher error tolerance and supplies gradient learning with more information for convergence. For example, if one spike is delayed or missed, several other spikes may still communicate that the input was strong. The cost is a larger number of events, which creates more synaptic processing and usually requires a longer observation window to estimate the rate.

Latency encoding places information in the time of a spike, often allowing each neuron to spike once for an input. An earlier spike can represent a stronger or more immediately recognized feature, while a later spike can represent a weaker response. One event now carries substantial meaning, so processing can finish quickly and with fewer operations. This makes latency coding faster and more power-efficient than rate coding. It also gives an online rule fewer update opportunities: the timing of each event must be used carefully because repeated spikes do not provide the same redundancy.

**Question.** Does online learning mean that every spike must change a weight?

**Answer.** Online learning means that updates can be computed while the temporal stream is being processed. A rule may update weights only for selected spikes, synapses, or learning signals. Event-driven operation supplies opportunities for updates; the learning rule decides which opportunities produce an actual change.

The comparison becomes clearer through memory and information flow. Full BPTT stores temporal states so a later objective can influence earlier computations. Online learning uses currently available information and carries only the state needed to continue processing. Local learning narrows that information further to signals available around a synapse or its connected neurons. Event-driven updates narrow the active computation to locations touched by spikes. These restrictions can preserve the sparse operating style that makes SNNs attractive, while reducing the global coordination available to objective-driven gradient optimization.

**Question.** Why would a network use rate encoding if latency encoding is faster and uses fewer spikes?

**Answer.** Rate encoding provides repeated evidence. Its multiple spikes tolerate individual timing errors and offer gradient-based learning more observations from which to adjust weights. Latency encoding concentrates information into one or a few precisely timed events, favoring speed and lower event counts. The useful choice depends on the data, the learning procedure, and the balance sought among accuracy, training behavior, latency, and energy use.

A useful mental model is to picture learning as the movement of information through space and time. BPTT gathers a temporal history and sends an error signal backward through it. Online learning updates while that history is still unfolding. Local learning keeps the update information near each synapse, and event-driven learning activates the process when spikes arrive. Rate coding supplies many update-bearing events, while latency coding asks a small number of precisely timed events to carry the message. Together, these choices determine how much information a learning rule can use, how long it must retain that information, and how closely training follows the sparse temporal character of the spiking network.
