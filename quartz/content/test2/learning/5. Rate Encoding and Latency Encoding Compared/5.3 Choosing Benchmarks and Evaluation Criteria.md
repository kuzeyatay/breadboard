## Choosing Benchmarks and Evaluation Criteria

Rate encoding and latency encoding give an SNN two different ways to represent the same input. Rate encoding uses the number or frequency of spikes observed over a processing interval, while latency encoding uses the time of a spike, often allowing each neuron to fire once for each input. Once these representations are understood, the experimental question becomes practical: what dataset and evaluation criteria will reveal whether the chosen encoding actually serves the intended application?

Imagine an SNN designed to recognize handwritten digits. Each example begins as a fixed grid of pixel intensities. Because the image has no built-in sequence of events, the experimenter must convert those intensities into spikes. Under rate encoding, a brighter pixel can produce a higher firing rate, such as a denser Poisson spike train. The network observes several opportunities for that pixel to spike, so the representation contains repeated evidence about its intensity. This repetition gives rate coding higher error tolerance and supplies gradient-based learning with more spike information, while requiring a longer processing period.

Latency encoding turns the same pixel intensity into spike timing. A strong input may produce an earlier spike and a weak input a later one. When each neuron fires once per input, the representation can be processed with fewer spikes and less waiting. The resulting experiment can therefore examine whether useful decisions emerge quickly and with low energy consumption. These properties make time-to-first-spike, or TTFS, encoding especially relevant when accuracy, processing speed, and energy consumption must be considered together.

The handwritten-digit experiment uses a **static-image benchmark**: a dataset whose examples are fixed images, such as MNIST or CIFAR-10. Static images are valuable when the intended capability is classification after an explicit conversion from pixel values to spike trains. They let the experimenter control how rate and latency encodings transform the same underlying information. If both encoding schemes receive the same images, differences can be studied within a shared task, provided the remaining experimental configuration is also kept comparable.

Dataset popularity can make such experiments easier to place alongside earlier work. MNIST and its variants appear frequently in SNN evaluations, and CIFAR-10 is another commonly used static-image dataset. Popularity alone, however, does not determine whether a dataset tests the desired capability. A static benchmark primarily tests the complete pipeline formed by image-to-spike conversion, network processing, and prediction. Performance on that pipeline combines the quality of the encoding with the behavior of the network and learning procedure.

Now imagine a sensor observing a changing scene or a signal unfolding through time. The order and timing of its observations carry information directly. An **event-based benchmark** preserves examples as streams of events rather than requiring every example to begin as a fixed image. Dynamic inputs such as speech or video make temporal structure part of the task itself. A latency-sensitive encoding can then use event timing as meaningful input, while a rate-based method can accumulate events over an interval and represent their intensity through firing frequency.

This leads to **task-aligned dataset selection**: choosing a dataset whose information structure matches the capability being tested. A static-image dataset is appropriate when the experiment asks how effectively a coding scheme converts fixed values into spikes for classification. An event-based dataset is appropriate when the experiment asks how effectively an SNN uses temporal information already present in the input. The benchmark should make the target capability observable. A study of rapid temporal response needs examples whose timing affects the decision, while a study of robust learning from repeated spike evidence needs an observation interval long enough for firing rates to become meaningful.

Neuromorphic and event-based datasets remain relatively niche and unstandardized, so many practitioners convert established non-neuromorphic datasets into spiking inputs. That choice creates a clear experimental responsibility: the conversion procedure becomes part of the evaluated system. A result obtained from rate-coded MNIST, for example, describes a model operating on a particular image-to-spike conversion over a particular processing period. Changing the conversion or the number of timesteps changes the information delivered to the network.

**Question.** If latency encoding is faster and uses fewer spikes, should every benchmark use it?

**Answer.** The benchmark should follow the capability being investigated. Latency encoding is well suited to experiments that value early decisions and low energy consumption, and it has been used to pursue high accuracy under those constraints. Rate encoding remains useful when repeated spikes provide error tolerance or additional information for gradient learning. The dataset must also fit the comparison: fixed images require an encoding step, while dynamic data can supply meaningful temporal structure directly. A justified choice therefore connects the input structure, encoding method, learning process, and application objective.

Evaluation criteria should follow the same alignment. Accuracy measures whether the network reaches the correct prediction. Processing time measures how long the network must observe spikes before producing that prediction. Energy consumption addresses the resource cost associated with the computation. Rate and latency encoding place different pressures on these criteria: rate coding benefits from observing enough spikes to estimate a firing rate, whereas latency coding can represent an input through a single spike time and can support earlier decisions with fewer events.

A useful evaluation states these criteria together rather than allowing one number to stand for the entire system. An experiment seeking maximum accuracy under low energy consumption must report enough information to show both parts of that objective. An experiment motivated by fast response must connect its result to the interval or number of simulation timesteps used before the decision. Accuracy measured after a long accumulation window answers a different question from accuracy measured after the earliest informative spikes.

This is **configuration-aware evaluation**: interpreting every result together with the conditions that produced it. The relevant configuration includes the dataset, architecture, encoding scheme, simulation timesteps, learning rule, software framework, and hardware setting. Comparisons become meaningful when these conditions are matched or when their differences are made explicit. Mixing accuracies across different datasets or processing windows can make an encoding appear stronger even though the systems received different information or had different amounts of time to compute.

**Question.** Why can two reported accuracies fail to provide a fair comparison even when both come from SNNs?

**Answer.** Accuracy depends on the whole experimental configuration. One model may process MNIST through rate-coded spike trains over many timesteps, while another may use latency encoding, a different dataset, another architecture, or a different learning rule. Each change alters the task or the conditions under which it is solved. A fair interpretation therefore pairs accuracy with the dataset and configuration, then compares speed or energy consumption only under similarly defined conditions.

A sound benchmark begins with the intended capability and works backward. The capability determines whether fixed spatial values or naturally timed events should form the input. That choice determines whether spike conversion is part of the experiment. The encoding scheme then determines how much observation time and how many spikes may be needed. Finally, the evaluation criteria measure the outcome the application actually values, while the configuration records the conditions that shaped it. Held together, these choices form a single mental model: a benchmark supplies the evidence, an encoding determines how that evidence enters the SNN, and a configuration-aware evaluation reveals whether the resulting system performs the intended job.
