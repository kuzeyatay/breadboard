## Rate, Latency, and Delta-Modulation Encoding

A spike train carries information through events distributed across time. Once spike timing can serve as part of a message, a practical question follows: how should an ordinary input value become those events? Imagine a camera pixel whose brightness changes while a short observation window is open. The pixel begins dim, grows bright, and then fades. A spiking system needs a rule that converts this changing brightness into a sequence of spike times. That conversion rule is called **spike encoding**. Different encoding rules preserve different properties of the same input, so the chosen rule shapes the information available to every later neuron.

**Rate encoding** represents input intensity through the number or frequency of spikes produced during an observation window. A stronger input leads to a higher firing rate, meaning more spikes occur per unit of time. For an image, each pixel can be assigned its own spike train: bright pixels generate spikes more frequently, while dim pixels generate them less frequently. The output therefore turns spatial intensity values into temporal event counts.

Suppose two pixels are observed for 100 milliseconds. A dim pixel produces two spikes, while a bright pixel produces eight. The count gives a downstream neuron evidence about their relative brightness. Individual spike times may vary, especially when spikes are generated through a probabilistic process such as a Poisson spike train, yet the overall rate still carries the intensity. Receiving eight events provides repeated evidence for a stronger stimulus.

This repetition gives rate encoding tolerance to timing variation and missing events. If one of the bright pixel's eight spikes shifts slightly or disappears, the remaining train can still indicate a high input intensity. It also provides many events through which a learning process can adjust its response. The cost appears in time and activity: estimating a rate requires observing enough of the spike train to distinguish a genuinely high rate from a temporary cluster of spikes. Longer windows usually make the estimate more stable, while also delaying when the encoded value becomes clear.

**Question.** If rate encoding represents one input value, why generate several spikes instead of one?

**Answer.** Several spikes make the value recoverable from an aggregate pattern. A downstream neuron can estimate intensity from the number of events collected over time, so small changes in individual event timing have limited influence. The same repetition requires additional activity and an observation period long enough for the count to become meaningful.

A different mapping places the information in the time of the earliest event. **Latency encoding**, often called **time to first spike** or **TTFS encoding**, assigns a shorter delay to a stronger input. Time begins at a shared reference point, such as the start of stimulus presentation. A large input produces a spike soon after that reference, while a small input produces one later. Each encoded input can therefore be communicated through a single spike.

Consider the same dim and bright pixels. The bright pixel might spike after 10 milliseconds, while the dim pixel spikes after 70 milliseconds. Their order immediately reveals which input is stronger, and their delays carry a graded representation of intensity. The downstream system reads *when* each event arrives rather than accumulating a count across many events.

Latency encoding uses time efficiently because information becomes available as soon as the relevant spike arrives. It also produces sparse activity when each input contributes only one event. Its representation depends strongly on precise timing: shifting a spike changes the encoded value directly. Rate encoding spreads intensity across repeated events, whereas latency encoding concentrates intensity into a single delay. The appropriate observation window still plays a role. It must be long enough to include the latest permitted spikes, and a neuron that has not yet spiked remains unresolved until its deadline passes.

A changing signal offers another useful property to encode. **Delta-modulation encoding** responds to changes in the input rather than repeatedly representing its current level. Here, "delta" means a difference. The encoder compares the current signal with a reference value and emits an event when the difference becomes large enough to cross a chosen threshold. A rising signal can produce one type of spike, often called an ON event, while a falling signal can produce another type, often called an OFF event. After an event, the reference updates so that later spikes report further changes.

Imagine that a brightness signal stays nearly constant for several moments and then rises sharply. During the steady interval, delta modulation remains quiet because the difference from its reference stays below the threshold. As brightness rises far enough, an ON event marks that change. Continued growth can trigger additional ON events as successive threshold-sized increases accumulate. When brightness falls, OFF events mark threshold-sized decreases. The resulting spike train emphasizes transitions, including when they occur and how frequently substantial changes continue.

The three mappings become easier to compare when they are applied to signals with visibly different amplitudes and shapes.

The rate-encoding portion links input magnitude to spike density: larger values correspond to more closely packed events. The latency portion links magnitude to delay: larger values move the first spike toward the beginning of the encoding interval. The delta-modulation portion follows the signal's movement: spikes gather where the input rises or falls enough to cross the change threshold, while relatively steady regions produce little activity. Thus, the same input can yield a repeated count, a single timed event, or a sequence of change events.

The delta threshold controls the granularity of this representation. A small threshold makes the encoder respond to smaller changes, producing more spikes that trace the signal more closely. A large threshold selects larger changes and produces fewer events. Input change rate also affects the output: rapid movement crosses successive thresholds quickly, so events cluster more closely in time. The train consequently preserves the timing and direction of significant changes, while the absolute level is represented indirectly through the accumulated history of those changes.

**Question.** Which encoding should be used when the input varies over time?

**Answer.** The decision follows from the input property that later processing needs. Rate encoding preserves intensity through event frequency and offers repeated evidence over a window. Latency encoding preserves intensity through first-spike timing and communicates each value with sparse, rapid events. Delta modulation preserves changes by emitting events when the signal moves far enough from its reference. A dynamic input can still use rate or latency encoding, and a static sample can be presented through a timed window; the encoding choice determines whether magnitude, arrival time, or change becomes most explicit.

A useful mental model is to imagine three observers watching the same signal. The rate observer counts how often a bell rings, the latency observer measures how soon the bell rings, and the delta observer listens for bells marking upward or downward movement. Each observer produces a valid spike representation, yet each makes a different feature easiest to recover. Spike encoding therefore serves as an information filter: rate exposes sustained intensity, latency exposes intensity through delay, and delta modulation exposes temporal change.
