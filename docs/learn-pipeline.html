Source Map, written in parts "Writing the Source Map in N parts"

callPartitionedSourceMap writes one part per source catalog, per unit's evidence and per practice source. Parts are merged mechanically (concatenate, de-duplicate anchors, renumber question IDs), and the merged map must pass whole-map validation. An additive update stays as one call.

  • Dropped with events: invented anchors, evidence pages that were not selected, unbound questions, excluded practice sources.
  • After the last healing pass, remaining gaps are recorded as limitations instead of failing the run.

6 · Publish writing_quartzcomplete

1
Atomic promotion "Publishing validated garden"

promoteStagingGarden is the only step that writes the repository garden (…/Data/quartz/content/<garden>):

  1. Copy the tree to a sibling temp directory.
  2. Verify it.
  3. Swap it in. The previous version is kept until the swap succeeds.

Edits made to the live garden during the run are merged in through a merge base, or refused as conflicts. On EBUSY or EPERM (OneDrive locks) it retries with exponential backoff. If promotion still fails, the old garden stays intact. The step waits if an upload to the garden is in progress.

Failure, cancel, pause, resume

  • Pause (pauseLatestLearnJob :20707) holds the run at the next checkpoint, between whole pages. Nothing is rolled back.
  • Cancel: cleanupLearnArtifactsAfterCancel removes or restores paths and deletes maps and versions. Status becomes cancelled ("latest Learn changes rolled back"). A cancelled full rebuild keeps its confirmed map.
  • Planning failure → rollbackLearnRun → learn_planning_rolled_back.
  • Generation failure → restorePreviousPromotedGarden and a republish. The workspace is retained (learn_failed_workspace_retained) so a resume replays accepted pages from their receipts.
  • Auto-resume (learn-auto-resume.ts) resubmits only for machinery causes: unsettled receipt, dead transport, held lease, worker torn down. It never does for quality failures (parked page, plan mismatch).
  • Startup recovery: recoverAbandonedLearnJobs and recoverPendingLearnPublications (:21862).

Model layer

  • Every call goes to ChatMock, which is OpenAI-compatible. Council routing fields (src/lib/council.ts) tell its council kernel the task kind: topic_map, source_map, scope_contract, learning_spine, subsection_generation, subsection_repair, visualization_generation, critique, …
  • Modes: direct_council (1 call), lite_council (candidate → review → synthesis), full_council, evolution_council.
  • Planning is pinned to direct; generation uses LEARN_GENERATION_COUNCIL_MODE (direct by default).
  • Retry authority comes from strict receipts, never from telemetry. A transport timeout first adopts the exact result before trying a new semantic attempt.
  • withUpstreamOverloadRetry (:15498) handles 429 and overload responses.
