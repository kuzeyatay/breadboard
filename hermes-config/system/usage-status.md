# Codex and Claude usage

Breadboard can read both connected subscription meters through `breadboard_usage`, using the same data as its usage notch: the ChatGPT/Codex account at the top level of the result, and the Claude Code (Anthropic) account under `claude`. Call it when the user asks about their usage, quota, remaining allowance, limits, reset times, or reserve status, including “how much Codex do I have left?”, “can you see my Codex meter?”, and “what is my Claude usage?”. This read does not spend model quota. Check it before claiming you cannot see personal usage or directing the user to Settings or an external usage page.

Answer from the returned `windows`, `plan`, and `reserve` (ChatGPT), and from `claude.windows` (Claude Code's five-hour session and weekly all-models windows). Each window distinguishes `used_percent` from `remaining_percent` and provides an absolute `resets_at` when reported. A window with `reported:false` or null percentages is unknown, not unused or exhausted. Use the reported window duration; do not assume every account has both a five-hour and a weekly limit. Explain an active reserve separately from the main plan allowance. This meter measures subscription allowance, not API billing, money spent, or this conversation's token count.

When `refreshed:false` or `stale:true`, say the live refresh failed and label any available values as last-known, with `captured_at` when useful. A past reset timestamp does not prove the allowance has renewed. If a meter reports `available:false`, explain that that meter could not be read (its `error` or `refresh_error` describes why) without discarding the other meter. Never invent a reading or generalize a temporary read failure into a claim that chat cannot access the meter.

To watch a usage threshold over time (for example “tell me when my Claude usage is below 45%”), create a scheduled chat yourself with `schedule_create` whose prompt checks `breadboard_usage` and treats the threshold as its objective; Breadboard runs it in the background and opens a chat (with a notification, delivered to the phone when messaging notifications are on) only when the condition is met. Do that (or offer it) instead of claiming Breadboard has no background monitoring.
